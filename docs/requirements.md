# 家計簿アプリ 要件定義書

## 1. 概要

個人の自用として使う家計簿Webアプリ。日々の収入・支出を記録し、月ごとに集計して確認できるようにする。まず最小構成で作り、運用しながら機能を育てていく。

## 2. 利用者

- 開発者本人1人（個人の自用ツール）
- 一般公開・不特定多数の利用は想定しない

## 3. 前提・仮定

- UIは日本語のみ
- 通貨は日本円のみ（金額は1円以上の整数）
- タイムゾーンはJST固定
- 利用デバイスはPC・スマホ両方のブラウザ（スマホでも入力しやすい画面にする）

## 4. 機能要件

### 4.1 認証

- インターネット公開するため、Amazon Cognitoによるログインを必須とする
- ユーザーは自分1人のみ。サインアップは開放せず、ユーザーは管理者（自分）がCognito上で作成する
- 未ログイン状態ではアプリの機能を一切利用できない

### 4.2 収支の記録（CRUD）

収支（収入・支出）を1件ずつ登録・一覧・編集・削除できる。

1件の収支が持つ項目：

| 項目 | 内容 | 必須 |
| --- | --- | --- |
| 日付 | 収支が発生した日 | 必須 |
| 種別 | 収入 / 支出 のどちらか | 必須 |
| 金額 | 1円以上の整数 | 必須 |
| カテゴリ | プリセットから1つ選択（4.3参照） | 必須 |
| メモ | 自由記述（例：店名・用途） | 任意 |

- 一覧は月単位で表示し、前月・次月へ切り替えられる
- 一覧は日付の新しい順に表示する
- 削除時は確認を表示する

### 4.3 カテゴリ

- カテゴリはアプリ側のプリセット固定とし、ユーザーによる追加・編集・削除はできない
- カテゴリは種別に紐づく。支出の収支には支出用カテゴリのみ、収入の収支には収入用カテゴリのみ選択できる。種別とカテゴリの組み合わせが一致しない登録・編集はエラーとする
- プリセット：
  - 支出：外食費、食費、日用品、交通費、住居費、光熱費、通信費、趣味・娯楽、医療・健康、サブスク、その他
  - 収入：給与、副収入、その他

### 4.4 月次集計

- 指定した月について以下を表示する
  - 収入合計、支出合計、収支差額
  - カテゴリ別の支出内訳（金額と構成比）
- 構成比は支出合計に対する割合を小数第1位で四捨五入して表示する。支出合計が0の月は構成比を0とする
- 収支一覧と同じ月切替UIから参照できる

- 毎月1日0:10（Asia/Tokyo）に前月分の集計をSNSの日本語プレーンテキストメールで通知する。
- 対象月はSchedulerの予定実行日時から決定し、遅延・再試行でも固定する。
- 件名・本文に対象月（YYYY 年 M 月）、本文に収入合計・支出合計・収支差額とカテゴリ別支出の金額・構成比を載せる。APIと同じ集計・丸め・順序を用いる。
- 月初・月末を含み前後月を除く。0件月も合計・差額0円、「支出内訳なし（0 円）」で送信する。
- バッチは読み取りだけ行い、削除・リセット・スキーマ変更はしない。
- 失敗は秘密情報を含めずCloudWatch Logsに記録し、Lambda非同期実行の再試行に任せる。重複送信は防止しない。
- 通知先はTerraform変数で設定し、SNS購読確認メールの承認を必要とする。画面設定・HTMLメールは対象外。

### 4.5 月額サブスクの管理

- 毎月発生するサブスクを登録・一覧・編集・削除できる。全操作でログインを必須とする
- 名前（必須、空白のみ不可、1〜100文字）、月額金額（必須、1〜2,147,483,647円の整数）、メモ（任意、500文字以内）を持つ
- 一覧は登録順で表示し、編集しても順序は変えない。同じ名前の登録は許可する
- 削除時は対象を表示して確認する
- 月次画面から管理画面へ遷移でき、管理画面から月次画面へ戻れる
- スマホ幅360pxでも一覧・入力・編集・削除を操作できる
- 支出のカテゴリ「サブスク」は通常の収支登録・編集でも手動で選択できる。収入では選択できない
- 管理するサブスクと実際の収支は別に保存する。管理画面の操作では登録済み収支を変更しない
- 毎月1日0:05 JSTに、実行時点の全サブスクを収支へ自動登録する。管理画面に日付指定は設けない
- 対象月は起動入力の予定日時（`scheduledTime`）をJSTに換算して決め、遅延・再試行でも変えない。登録日は対象月1日、種別は支出、カテゴリはサブスク、金額はサブスク金額、収支メモはサブスク名とする（サブスクのメモは使わない）
- 登録台帳 `subscription_registrations` のサブスクID・対象月の複合ユニーク制約で二重登録を防ぐ。同月の再実行・同時実行でも同一サブスクの収支は1件とする
- 台帳と収支は1トランザクションで登録し、失敗時は全体をロールバックする。サブスク0件なら何も登録せず正常終了する
- 登録した収支は通常の収支として編集・削除できる。台帳は残るため、削除後も同月の再実行で復活しない。台帳はサブスク・収支への外部キーを持たず、サブスクの編集・削除は登録済み収支に影響しない

### 4.6 レシート登録

- 月次画面からJPEG・PNG・WebP画像（1バイト〜10 MiB）を選択し、認証済みの `POST /api/receipts/upload-url` で5分間有効なPUT用署名付きURLと `jobId` を取得する。画像は非公開S3へ直接アップロードする
- URL発行時に解析ジョブを「待機中」で作成し、S3のObjectCreatedを起点にBedrockで解析する。状態は「待機中」「完了」「失敗」
- 候補は日付・税込合計金額（円）・店名・支出カテゴリ。読めない項目はnull。日付は `yyyy-MM-dd` の実在日、金額はJSON数値の整数値かつ1〜2,147,483,647円、カテゴリは支出プリセットと完全一致した値だけ保存する。店名は前後の空白を除き1〜100文字
- 項目単位の不正値はその項目だけnullにして完了する。画像取得・モデル呼び出し・JSONオブジェクトの解析に失敗すると「失敗」。画像が3,750,000バイトを超えるとモデルを呼ばず失敗とする（アップロード上限とは異なる）
- 認証必須の `GET /api/receipts/{id}` で状態・候補・作成日時・更新日時を取得する。存在しないIDは404。S3キーは公開しない
- 画像は7日後にライフサイクルで削除される。解析ジョブの行は保持する。アップロードしなかった場合やLambdaが異常終了した場合は待機中のまま残る
- 結果表示・収支フォームへの反映・自動登録は後続Issueとする

## 5. 画面構成（概要）

| 画面 | 内容 |
| --- | --- |
| ログイン | Cognitoのログイン |
| 月次画面 | 月切替、収支一覧、月次集計（合計・カテゴリ別内訳）を一体で表示、レシート画像のアップロード |
| サブスク管理 | 月額サブスクの登録順一覧、登録・編集フォーム、削除確認 |
| 収支の登録・編集 | 4.2の項目を入力するフォーム（新規登録と編集で共用） |

## 6. 技術構成・非機能要件

- フロントエンド：React（SPA）。S3で静的ホスティングして公開する
- バックエンド：.NET製のWeb API。AWS Lambdaで動かす
- データベース：PostgreSQL（NeonのサーバーレスPostgreSQLを使用）
- 認証：Amazon Cognito
- レシート解析：S3イベントから起動するLambdaとAmazon Bedrock（Claude）
- 開発環境はDocker（Docker Compose等）で構築し、ローカルでの開発・動作確認に使う。コンテナ構成（ローカル用PostgreSQL等）の詳細は設計工程で決定する
- インフラ構築方法（SAM / CDK / Terraform 等）やAPI Gateway・CloudFrontの要否などの詳細は設計工程で決定する
- 個人利用のため高いパフォーマンス・可用性は求めない。AWS・Neonの無料枠または最小コストで運用できる構成にする
- テストコードを実装とあわせて作成し、CIでテストを実行できるようにする（詳細は設計工程で決定）

## 7. スコープ外（今回作らないもの）

以下は最小構成に含めない。必要になった時点で別途要件を定義する。

- 予算設定・予算消化率の表示
- グラフ・レポート機能（カテゴリ別内訳の数値表示は含む）
- サブスク以外の定期収支（固定費）の自動登録（サブスクの管理・月初の自動登録は4.5の対象内）
- 年額・隔月など月額以外のサブスク、引き落とし日の指定、一時停止（停止時は削除する）
- CSV等のインポート・エクスポート
- 銀行・カード連携
- レシートの品目明細の抽出と複数収支への分割
- 収入（給与明細など）の解析
- 解析精度の継続的な評価
- 解析結果の収支フォームへの反映と自動登録（後続Issue）
- 複数口座・複数通貨の管理
- カテゴリのユーザー編集
- 複数ユーザーでの共有

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| 収支 | 収入または支出の1件の記録 |
| カテゴリ | 収支の分類（プリセット固定） |
| 月次集計 | 指定月の合計・カテゴリ別内訳 |
| サブスク | 名前・月額金額・メモで管理する毎月の継続支出。実際の収支とは別の登録情報 |
| 解析ジョブ | URL発行時に作成し、レシート解析の状態と検証済み候補を保持する記録 |
