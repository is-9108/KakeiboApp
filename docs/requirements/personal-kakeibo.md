## 1. 目的・背景

本人が収入・支出を手入力し、月ごとの収支とカテゴリ別支出を把握するための新規Webアプリ。特に食費と外食費を別々に把握できることを重視する。既存コード・仕様書はない。

## 2. 利用者とユースケース

| ID | 利用者 | ユースケース |
|----|-------|-------------|
| UC-001 | 本人1人 | 認証して日々の収支を入力する |
| UC-002 | 本人1人 | 誤入力を編集・削除する |
| UC-003 | 本人1人 | 月別の取引、収支、カテゴリ別支出を確認する |
| UC-004 | 本人1人 | 収入・支出それぞれのカテゴリを管理する |
| UC-005 | 本人（運用者） | 通知を確認し、必要時にバックアップから手動復旧する |

スマホ優先、PCでも利用する。本人がAWS/Neonアカウントおよび通知メールを用意し運用する。

## 3. スコープ

### 対象（すべてMVP）

収支登録・一覧・編集・削除、月別収支、カテゴリ別支出の表とグラフ、カテゴリ管理、本人認証、レスポンシブUI、セキュリティ、バックアップ、運用通知、性能検証、AWS構成のIaC化。

### 対象外

口座残高、家計の予算管理、定期取引、銀行/カード明細取込、CSV出力、家族共有、全文検索、年集計、オフライン対応、独自ドメイン。将来の追加順は未指定。クラウド費用通知は対象内であり、家計の予算管理とは異なる。

## 4. 機能要件

全機能の優先度は **Must**。共通エラー方針はFR-012に従う。

### FR-001: 収支登録

- **概要**: 手入力した取引を保存する。
- **入力**: 日付、収入/支出種別、カテゴリ、金額は必須。メモは任意。
- **処理**: FR-002の検証後にNeonへ保存する。種別に対応するカテゴリを使う。
- **出力**: 保存結果。再読込しても保存した取引を参照できる。
- **エラー時の振る舞い**: 不正入力は保存せず項目別エラーを表示。通信/サーバエラーは入力を画面内保持して再試行可能。

### FR-002: 取引入力の検証

- **概要**: 登録・編集で同じ入力制約を適用する。
- **入力**: FR-001の項目。
- **処理**: 金額は日本円のみ、1〜999,999,999円の整数（負数・0・小数不可）。日付は日本時間の暦日で2000年〜2100年を両端含む。未来日も許可。メモは任意で500文字まで。必須値・カテゴリと収支種別の整合性を検証。
- **出力**: 有効入力または項目別エラー。
- **エラー時の振る舞い**: 不正値を永続化しない。ブラウザだけでなく保存処理側でも制約を保証する。

### FR-003: 登録再送の重複防止

- **概要**: 同一登録リクエストの再送は重複取引を作らない。
- **入力**: 初回および再試行の登録リクエスト。
- **処理**: 同一リクエストを識別して重複保存を防ぐ。送信中はボタン無効。
- **出力**: 再送後も保存された取引は1件。
- **エラー時の振る舞い**: 結果を受信できなかった場合も入力を保持して再試行できる。識別方式は設計で定める。

### FR-004: 月別取引一覧

- **概要**: 選択月の取引をページ単位で確認する。
- **入力**: 年月、ページ指定。
- **処理**: 初期は日本時間の当月。日付降順、同日は登録の新しい順。50件ずつ取得・表示する。
- **出力**: 選択月の該当取引一覧。
- **エラー時の振る舞い**: FR-012に従う。

### FR-005: 取引一覧の絞込

- **概要**: 選択月の一覧を収支種別・カテゴリで任意に絞り込む。
- **入力**: 年月、任意の収支種別/カテゴリ、ページ指定。
- **処理**: 絞込後もFR-004の順序と50件単位を維持する。FR-008/009の集計は絞込の影響を受けない。
- **出力**: 条件に合う一覧。
- **エラー時の振る舞い**: FR-012に従う。

### FR-006: 取引編集

- **概要**: 保存済み取引を修正する。
- **入力**: 対象取引と修正値。
- **処理**: FR-002の検証後に保存する。競合は後の保存優先。
- **出力**: 変更後の記録。再読込後も変更を確認できる。
- **エラー時の振る舞い**: 不正値は保存しない。通信/サーバエラー表示と画面内入力保持・再試行。

### FR-007: 取引削除

- **概要**: 確認した取引を削除する。
- **入力**: 対象取引、削除確認。
- **処理**: 確認必須。確認後に削除する。
- **出力**: 削除結果。再読込後も通常画面に表示されず、通常画面から復元不可。
- **エラー時の振る舞い**: 通信/サーバエラーを表示。確認取消時は削除しない。

### FR-008: 月別収支集計

- **概要**: 月全体の収支を把握する。
- **入力**: 選択年月。
- **処理**: 一覧の絞込とは独立して選択月全体を集計。
- **出力**: 収入合計、支出合計、差額（収入−支出）。0件は0円表示。
- **エラー時の振る舞い**: FR-012に従う。

### FR-009: カテゴリ別支出集計

- **概要**: 月の支出内訳を表とグラフで確認する。
- **入力**: 選択年月。
- **処理**: 月全体のカテゴリ別支出額と割合を計算。食費と外食費を別集計。カテゴリ名変更は過去分にも反映。
- **出力**: 額と割合の表およびグラフ。0件は0円表示。
- **エラー時の振る舞い**: FR-012に従う。ゼロ支出時の割合表示・丸め・グラフ形式は後続設計で定める（0円表示を変更しない）。

### FR-010: 初期カテゴリ

- **概要**: 利用開始時からカテゴリを選択できる。
- **入力**: 初期構築。
- **処理**: 支出は「食費、外食費、日用品、住居、水道光熱、通信、交通、医療、娯楽、その他」、収入は「給与、副収入、その他」を初期登録。
- **出力**: 収支種別別のカテゴリ一覧。
- **エラー時の振る舞い**: 初期構築失敗を検出し、不完全な初期データのまま公開しない。

### FR-011: カテゴリ管理

- **概要**: 種別別に追加、名前変更、未使用カテゴリの削除を行う。
- **入力**: 収支種別、名称、対象カテゴリ。
- **処理**: 名称1〜30文字。同一種別内の同名は禁止、種別変更不可。名前変更は過去分にも反映。使用中カテゴリは削除不可。
- **出力**: カテゴリ一覧と変更結果。
- **エラー時の振る舞い**: 同名・不正名称・使用中削除を拒否し表示する。通信/サーバエラー時はFR-012に従う。

### FR-012: 共通操作・エラー表示

- **概要**: 誤操作や通信失敗から回復できるUIを提供する。
- **入力**: 画面操作、処理結果、通信/サーバエラー、認証切れ。
- **処理**: 送信中はボタン無効。不正入力は項目別に表示。通信/サーバエラーを表示し、入力は画面内保持して再試行できる。認証切れは再ログイン案内。
- **出力**: 操作結果・エラー・再試行/再ログイン案内。
- **エラー時の振る舞い**: オフライン永続保存は行わない。画面内保持はリロード後の復元を保証するものではない。

### FR-013: 本人認証

- **概要**: 本人だけがアプリとAPIを利用できる。
- **入力**: 本人のCognitoアカウント、認証アプリのTOTP。
- **処理**: 公開サインアップなし、MFA必須、本人1アカウント限定。APIでも許可された本人IDを確認。
- **出力**: 本人ログイン成功時に利用可能。
- **エラー時の振る舞い**: 未認証・本人以外は拒否。認証切れは再ログイン案内。

## 6. 外部インターフェース

- React＋TypeScriptの日本語レスポンシブWebをS3/CloudFrontで配信。CloudFront既定ドメイン、独自ドメインなし。
- JSON/RESTでAPI Gateway HTTP API＋C#/.NET Lambdaへ接続。実装時点のLambda対応.NET LTSを採用。
- Cognitoと認証アプリのTOTPを利用。
- Neon PostgreSQLのプール接続。AWSリージョナルリソースは東京 `ap-northeast-1`、Neonのみシンガポール `aws-ap-southeast-1`（2026-10-09の明示回答、`.pi/harness/issue-1-r4/qa.md`）。CloudFront/IAMはグローバルサービス。
- Secrets Manager、バックアップ用非公開S3、通知メールを利用。
- CLI・ファイル取込・GPIO等のアプリ利用インターフェースはなし。ただし構築・運用手段としてのCLI等は禁止しない。

## 7. データ

| データ | 保存先 | 形式・管理 | 保持期間 |
|--------|--------|------------|----------|
| 取引 | Neon PostgreSQL | 日付・種別・カテゴリ・円整数金額・任意メモ。具体スキーマは設計、マイグレーション管理 | 期限なし（確認後に削除したデータを除く） |
| カテゴリ | Neon PostgreSQL | 種別・名称。過去取引に名称変更を反映する関係を維持 | 期限なし（未使用カテゴリの削除を除く） |
| DBバックアップ | 暗号化・非公開S3 | 具体方式は設計、日次取得 | 30日 |
| 運用ログ | AWS側のログ基盤（具体設定は設計） | NFR-005の項目のみ | 30日 |

削除データは通常画面から復元不可。バックアップからの手動復旧は運用者の作業であり、通常画面の復元機能ではない。

## 8. 制約・前提

- 本人1人用、新規開発、納期指定なし。全対象要件がMVP。
- アカウント・メール等の具体値は本人が構築時に用意する。秘密値を要件書・Issue・ログへ記載しない。
- IaCツール、APIパス、グラフ形式、バックアップ方式、性能測定詳細、通知実装方式は後続設計へ委任済み。
- サービス対応状況・費用は設計時に確認。AWS東京・Neonシンガポール・Lambda対応.NET LTS・プール接続を含め、合意制約を勝手に変更しない。
- Neon公式一覧に東京がないため、今回回答に基づきNeon地域のみ変更した。地域間通信の遅延・転送課金は未検証であり、NFR-001/007の性能・費用目標は緩和しない。不適合見込みなら該当実装前に再相談する。
- 予算・性能を満たせない見込みの場合は実装前にユーザーへ相談する。
- IssueはS/Mのみ、1つの受け入れ可能な振る舞い、受け入れ条件5個以下。依存・並行可否は別紙参照。

## 11. 用語集

| 用語 | 意味 |
|------|------|
| 取引 | 1件の手入力された収入または支出 |
| 月 | 日本時間の暦日で分類した選択年月 |
| 同一登録リクエスト | 初回送信とその再試行として識別される要求。同額・同日というだけで別取引を排除しない |
| p95 | 応答時間の95パーセンタイル |
| TOTP | 認証アプリが生成する時間ベースのワンタイムパスワード |
| 並行可 | 分割案の依存が完了した後、共有契約を変更せず別担当で同時作業可能 |
