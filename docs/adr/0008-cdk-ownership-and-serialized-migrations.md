# ADR 0008: CDK・所有範囲・migration/共有変更の直列管理

- 状態: Accepted
- 決定日: 不明（CDK・所有範囲・直列管理の決定日を裏付ける記録なし）
- 記録日: 2026-10-09

## 背景

【事実】[業務要件§5](../requirements/personal-kakeibo.md#5-非機能要件)のNFR-009/011はAWS構成のIaC化、DBのmigration管理、依存・競合注意の明示を求める。契約§8は機能ごとの所有範囲と共有組込みの管理者を定めている。所有パスは後続で作るもので、実装済みではない。

【当時の理由】契約§8に記録されたCDK採用理由は「Webと同言語、AWS構成/独立construct/CloudFormation差分管理」。所有範囲・直列管理の採用理由については、当時の記録なし。以下のトレードオフは今回の整理であり、過去理由の補完ではない。

## 決定

以下はすべて【事実】として[契約§8](../design/personal-kakeibo.md#8-所有ファイルと独立拡張点)の既存判断を記録する。

### CDKと管理境界

- AWS CDK TypeScriptを採用し、AWS構成は全てIaCとする。Terraformは今回不採用、既存stateなし。
- Neon project作成はAWS CDK対象外で、3の手順/設定管理に残す。実DB migration実行基盤は1/2が整備する。
- transaction poolingに非対応の運用ツールは2/28が接続方式を別途確認する。本ADRで直接接続などの運用方式を新決定しない。

### 所有範囲と共有変更

- 1がroot・manifest/依存/lock・共有組込みを所有し、1→0契約管理がDTO/Errors等の唯一の共有型を管理する。2はmigrationの採番/履歴/実行の管理者。各feature担当は専用ファイル・construct・export・テストを扱い、共有ファイルを無断変更しない。
- 共通route/DI/画面slotは管理者が単独接続する。13/18/9の合成ファイルへの組込みは各管理者が直列処理し、担当は登録要求と専用export/テストを提出する。
- 未完成delegate/validatorを成功扱いするstub経路は非公開。全制約完成後の契約試験を必須とする。分離不能な14/15/16は14→15→16、登録本体変更は13完了後17が単独、共有Page変更も直列化する。
- 共有契約変更は、影響担当へ通知→関係作業停止→管理者単独で契約/DTO/合成点変更→要件変更なら本人承認→影響テストと契約レビュー→担当確認後再開とする。
- IaC root/依存/lock変更は1の管理者がqueueで直列処理し、同一stackへの同時deployは禁止。専用construct担当は共有設定や秘密を無断追加しない。
- origin/issuer/secret参照の共有変更は1/3/4/5で単独調整し、秘密実値をprops/出力/文書へ露出しない。既存依存表を維持する。

### migration・配備・復旧

- 2が0003以降の番号と依存順を予約し、各Issueは別SQLファイルを作る。適用済みSQLの改変は禁止する。
- 実行は単一実行者とtransaction advisory lockを使用し、履歴/checksumを記録、不一致なら停止する。共有schema変更は通知/停止/新migration/試験/再開とし、schemaとfeatureの配備順も予約する。
- 追加互換変更はmigration→新API→Webの順で配備し、旧APIとの互換性試験後に再開する。
- 破壊的変更は関係API停止→バックアップ→migration→API/Web更新→契約試験→再開。失敗時は公開しない。
- 回復は適用済みSQLを書き戻さず、新migrationまたは承認済み復元手順による。復元に再送記録/sequenceとカテゴリ参照を含め、復元/負荷/ブラウザ試験DBを分離する。

## 代替案

【事実・記録済みの採否】契約§8にCDK採用、Terraform今回不採用、既存stateなしの記録がある。記録済みの採用理由は背景に示した範囲のみであり、Terraformの詳細な比較理由は当時の記録なし。

【今回の整理・比較分析】CDKのTypeScriptと独立constructは、Webと同言語で専用担当とroot管理者を分ける既存契約に対応する。一方、AWS構成のIaC化だけではNeon projectとDB migrationの管理は完結せず、別の責任境界が必要になる。Terraformの能力・費用・性能の優劣はこの資料から判断しない。他方式を当時検討したとも主張せず、採否を再設計しない。

## 影響・トレードオフ

【今回の整理・比較分析】専用ファイルでの並行作業と共有変更の直列化を分けることで、責任と変更順を追跡しやすくし、共有部の競合を抑えられる。一方、管理者のqueue待ちや関係作業停止が生じる。migrationの履歴/checksumと改変禁止は追跡性を保つが、回復にも新migrationまたは承認済み復元の調整が必要になる。これらは効果の実測や運用保証ではない。

【事実】文書はGitで履歴管理する。将来の判断変更では旧ADRを削除せず、新ADRとSupersededリンクで追跡する（[ADR共通要件§7](../requirements/common-contract-adr.md#7-データ)）。今回は変更判断を行わない。

## 未検証・後続ゲート

【未検証】実配備、migration実行、履歴不一致時の停止、旧API互換性、破壊的変更時の回復は本件で試験しない。[契約§9](../design/personal-kakeibo.md#9-fr追跡と後続試験)のユニット/実DB結合/UI・実環境証跡を省略せず、ADR作成を公開ゲート合格としない。

【事実・保持する制約】[契約§1](../design/personal-kakeibo.md#1-全体構成と提供状況)と[業務要件§5](../requirements/personal-kakeibo.md#5-非機能要件)を変更しない。

- 通常API p95 2秒、休止後初回10秒、AWS＋Neon合計月3,000円の目標を緩和しない。地域間遅延/転送課金、休止/接続上限を含め未検証。不適合見込みなら該当実装前に再相談し、無合意のDB/地域変更は禁止。
- 日次暗号化・非公開S3バックアップ30日、最大24時間データ損失、48時間以内手動復旧を維持する。バックアップ方式は今回決めない。
- ログはrequestId/処理時間/結果・エラー分類のみ30日保持。body、金額、メモ、token、接続文字列、本人IDを記録しない（[契約§3](../design/personal-kakeibo.md#3-エラーとui接続)）。ログ/運用機能を追加せず、Raspberry Pi 5は不使用。

【未検証・後続担当】[業務分割案](../requirements/personal-kakeibo-issues.md)の28でバックアップ設計、32で隔離DB復元試験、33/34で合計費用方式/通知、36/37で性能手順/実測、35/38/39でセキュリティ/ブラウザ検証を行う。40は全証跡後の公開判定。費用通知方式・性能測定詳細も本件で決めず、未達/相談中は公開しない。
