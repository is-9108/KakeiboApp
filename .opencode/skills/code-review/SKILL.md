# コードの観点でレビューする

依頼ファイル（request.md）に書かれたPR・issue・プラン・コードの場所を使う。コードは変更しない。書いてよいのは結果ファイルだけ。

依頼ファイルの「確認範囲」が前回からの修正差分なら、PR全体を読み直さない。前回の指摘の箇所と、差分とその呼び出し元だけを見る。

## 確認すること

1. バグ：誤った条件、境界の扱い（0・負数・空・最大値・月末など）、null/未定義、例外の握りつぶし
2. 金額や日付の計算誤差（浮動小数点、タイムゾーン）
3. セキュリティ：入力検証、インジェクション、秘密情報の混入
4. 保守性：重複、既存コードの流儀と合わない書き方、不要な変更
5. 依頼ファイルに前回の指摘があれば、コードに関するものが直っているか

差分だけでなく、呼び出し元など周辺のコードも読んで判断する。

## 結果ファイルの形式

```markdown
# コードレビュー：PR #<PR番号>（<回数>回目）

## 指摘
1. **箇所**：`path/to/file:行`
   **内容**：
   **起きること**：<どんな入力・状態で何が起きるか>
   **修正案**：

## 前回指摘の対応状況
- <指摘>：対応済み / 未対応（理由）

<!-- 完了 -->
```

- 根拠を示せない推測は書かない
- 指摘がない区分には「なし」と書く
- 最後の行は必ず `<!-- 完了 -->` にする
