# 独立した二視点のレビュー

## 窓口の準備

1. 依頼がレビューだけなら実装や修正は行わない。
2. レビュー対象を明示する。コミット範囲なら明示された BASE..HEAD、作業中なら staged・unstaged・untracked をすべて確認する。git diff だけでは未追跡ファイルを含まない。Git がなければ変更ファイルと比較対象・限界を明示する。
3. プロジェクトの絶対パス、対象範囲、要求・計画のパス、関連ファイル、検証結果を同じ入力として用意する。大量の差分は必要なときだけ docs/changes/<変更名>/review-diff.patch に保存し、未追跡ファイルも別途指定する。秘密情報を含めない。保存希望のない単独レビューでは一時 patch を作らず、差分を入力に渡すか既存対象を読ませる。
4. harness-review-spec と harness-review-quality を独立した新しい子セッションで呼ぶ。安全に読める同じ状態なら並行実施してよい。他方の結論や過去の review.md は渡さない。
5. レビュー中はコードを変更しない。ユーザー等の変更を検出したら影響範囲をレビューし直す。モデルは agent 設定を使い、利用不能なら停止して相談する。

## 各レビュアーの仕事

自分の agent に割り当てられた観点だけを担当し、コード・仕様・テストを読む。実装者の説明だけで合格としない。具体的なリスクを調べるための呼び出し元や関連実装の確認は行ってよい。

- **spec**: 完全性（要求漏れ）、仕様適合（振る舞い）、整合性（設計・互換性・文書）。
- **quality**: 正確性、境界値・異常系、テストの有効性、安全性、関連する運用・性能・復旧。
- 未確認の項目は「未検証」、変更に関係しない項目は「対象外」とする。テスト実行の報告と自分の静的確認を区別する。
- レビューは読み取り専用。ファイル編集・追加 agent・shell は使わない。必要な再現テストは窓口に依頼する。

親へ次の形式で返す。

```markdown
## 判定
観点: spec または quality
判定: 問題なし / 要修正 / 未検証あり
確認対象: <範囲・ファイル>

## 指摘
- ID: SPEC-1 または QUALITY-1
- 重要度: 重大 / 重要 / 軽微
- 場所: <file:line、または欠落している要求の参照>
- 条件と影響: <何をすると何が壊れるか>
- 根拠: <コード・仕様・検証結果>
- 対応案または必要な確認: <具体的なもの>

## 未検証・対象外
<項目と理由。なければ「なし」>
```

重要度は実際の影響で決める。重大は安全性・データ損失・主要機能の破損、重要は要求漏れや正確性の欠陥、軽微は改善提案。推測だけの危険を重大と断定しない。

## 統合・修正・完了

1. 窓口は両レポートと検証結果をまとめる。単独レビューは原則会話で返し、単純な統合は窓口、複雑な食い違いは writer にテキスト統合を依頼する。単独レビューの保存は依頼時のみ、通常実装後の完了レビューは writer が docs/changes/<変更名>/review.md に保存する。保存のない場面では review.md を作らない。既存の別レビューを消さない。
2. 食い違いは多数決で解決しない。追加確認が必要なら窓口経由で implementer に具体的な検証を依頼する。要件や許容リスクを変えるならユーザーへ確認する。
3. 修正許可があり、根拠が確認された未解決の重大・重要指摘を implementer に返す。レビューだけの依頼では指摘を修正しない。会話で返した指摘でも、後から修正依頼があればその依頼の範囲を渡せる。修正後は元の担当レビュアーへ指摘ID・修正差分・新しい検証結果を渡し、修正とその副作用に絞って再確認する。
4. 同じ問題の修正が2回失敗したら止めて相談する。未解決の重大・重要指摘を上限到達だけで合格や完了にしない。
5. writer は指摘ごとの状態（修正済み / 未解決 / 誤検出と根拠 / ユーザー承認済み保留）と両観点の確認範囲、実行コマンド・結果、未検証事項を記録する。再確認前に修正済みにしない。
6. 通常の完了報告前に、要求・タスクと最終コード状態に対する検証を照合する。独立レビューが合格でも、テスト未実行なら「検証完了」としない。
7. 現行仕様の更新が必要なら、確定内容を writer が docs/specs/ の該当箇所へ反映する。仕様の更新をコミット・公開・リリースの完了と同一視しない。

review.md は一つで十分。複数の台帳、機械的な状態ファイル、形式だけのアーカイブは作らない。
