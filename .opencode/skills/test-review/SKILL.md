# テストの観点でレビューする

依頼ファイル（request.md）に書かれたPR・issue・プラン・コードの場所を使う。依頼ファイルの「確認範囲」が前回からの修正差分なら、前回指摘の対応確認と、その差分で新たに生じた問題だけを見る。コードは変更しない。書いてよいのは結果ファイルだけ。

## 確認すること

1. 実装プランのテストケース一覧の各IDがテストコードになっているか。抜けているIDを挙げる
2. 各テストが期待結果を具体的に検証しているか（実行するだけで何も確認しない、常に通る、実装をなぞっているだけ、などを指摘する）
3. プランの期待結果より弱い検証に変えられていないか
4. 正常系・異常系・境界値が揃っているか。プランにない重要な境界値があれば挙げる
5. 依頼ファイルに前回の指摘があれば、テストに関するものが直っているか

## 結果ファイルの形式

```markdown
# テストレビュー：PR #<PR番号>（<回数>回目）

## 指摘
1. **箇所**：`path/to/test:行`
   **内容**：
   **根拠**：<該当するテストコードとプランの記述の引用>
   **修正案**：

## テストケースの対応
| プランのID | テストコード | 判定 |
| --- | --- | --- |
| T1 | `path:行` | OK / 弱い / なし |

## 前回指摘の対応状況
- <指摘>：対応済み / 未対応（理由）

<!-- 完了 -->
```

- 根拠を示せない推測は書かない
- 指摘がない区分には「なし」と書く
- 最後の行は必ず `<!-- 完了 -->` にする
