# issueを作る

## テンプレートを選ぶ

- 設計から分割したタスク → `.github/ISSUE_TEMPLATE/feature.md`（ラベル `enhancement`）
- 実装中に見つけたバグ・追加タスク → `.github/ISSUE_TEMPLATE/bug.md`（ラベル `bug`）

## 本文を書く

1. テンプレートを読み、frontmatter（`---` で囲まれた部分）を除いた見出しをそのまま使う。見出しを足したり削ったりしない
2. `<!-- -->` のコメントは消し、指示に沿って中身を書く。書くことがない見出しには「なし」と書く
3. 受け入れ条件は必ず書く。テストで検証できる書き方にする（「〜のとき〜になる」）。曖昧な形容詞（「適切に」「正しく」）を使わない
4. 設計から分割するときは、1つのissueが1つのPRで終わる大きさにする。依存するissueがあれば「依存」に番号を書く
5. タイトルと本文は日本語で書く

## 作成する

本文を一時ファイルに書いてから作る（`--body` に長文を直接渡さない）。

```
gh issue create --title "<タイトル>" --label <ラベル> --body-file <一時ファイル>
```

作成後、issueの番号とURLを報告する。設計から複数のissueを作った場合は、番号・タイトル・依存関係を一覧にして報告する。
